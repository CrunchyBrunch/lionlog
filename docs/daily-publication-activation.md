## Monitoring and recovery

Configure GitHub Actions failure notifications for the owner and watch the `Daily verified LionLog publication` run, its exact three downstream run links in the step summary, public release marker, and checkpoint branch. A scheduled failure leaves the previous public bytes in place; the app's existing freshness and retention labels apply. A candidate or promotion failure does not trigger another scheduled full scrape. A failed public verification cannot advance the checkpoint. A checkpoint failure after a successful publication requires investigation before the next day, because the public predecessor may have moved while the authenticated state did not.

GitHub documents that schedule events can be delayed or dropped and can be disabled after 60 days of inactivity in public repositories. Checkpoint commits on a non-default state branch are **not** established here as satisfying GitHub's activity criterion. Native Actions failure notifications report a run that starts and fails; they cannot detect an event that never starts. The owner needs an independent heartbeat check if absence detection is required for indefinite daily operation. This PR does not set up an external scheduler or monitor.
